# Designer Maturity Intelligence

**Evidence-based professional maturity assessment and personal development operating system.**

Designer Maturity Intelligence (DMI) helps designers assess professional capabilities using evidence, separate strategic thinking from execution and impact, identify career positioning, and turn findings into a sustainable 30/60/90-day development plan.

> **Important:** DMI is a structured reflection framework, not a psychometric test, formal HR certification, or independently validated industry benchmark. Scores are estimates and must reflect the evidence available.

## Start here

1. Open [the assessment prompt](./PROMPT.md).
2. Copy the complete prompt into an AI chat that supports long-form instructions.
3. Let the AI complete the written assessment and development plan before generating any visual.
4. Review and challenge the evidence, scores, confidence labels, and recommendations.
5. Only after the written report is complete, choose the JPG infographic (A) or interactive HTML dashboard (B).

## Core principles

- **Evidence before scoring:** distinguish direct, self-reported, behavioral, inferred, and missing evidence.
- **Thinking / Execution / Impact:** evaluate each competency in three separate dimensions.
- **No invented proof:** ambition, implementation, adoption, and measurable impact are different evidence levels.
- **Transparent uncertainty:** include confidence and limitations; missing evidence is not automatically a capability gap.
- **Consistent scoring:** use the defined 0–10 scale and domain weighting where evidence supports a score.
- **Development through application:** connect each priority to real work, feedback, artifacts, and review milestones.
- **Sustainable scope:** no more than three active development priorities.
- **Human confirmation for visuals:** finish the written report before asking the user to choose JPG (A) or interactive HTML (B).
- **Longitudinal continuity:** compare future evidence with the original baseline; never fabricate historical scores.

## Eight competency domains

- Design Strategy & Systems Thinking
- User Research & Experience Quality
- Product Thinking & Business Impact
- Interaction & Visual Design
- Design Systems & DesignOps
- Technical & Delivery Capability
- AI, Automation & Innovation
- Leadership, Communication & Mentorship

Each domain is assessed through Thinking, Execution, and Impact. The domain formula is:

**Domain Score = (Thinking × 0.40) + (Execution × 0.40) + (Impact × 0.20)**

Dimension/domain score bands: 0–1.9 Not demonstrated; 2.0–3.9 Emerging; 4.0–5.4 Developing; 5.5–6.9 Proficient; 7.0–8.4 Advanced; 8.5–9.4 Expert; 9.5–10 Exceptional. These are framework guidelines, not industry norms. They are distinct from the five maturity levels; maturity-level score bands are only orientation guidance and cannot override evidence gates. See the maturity calibration rubric in [PROMPT.md](./PROMPT.md).

## Maturity levels

1. Foundational
2. Developing
3. Independent
4. Strategic / Systemic
5. Transformational

Level 5 requires evidence of sustained adoption, repeatability, organizational influence, and impact—not just sophisticated proposals or tools.

## Professional profile classification (separate from maturity)

DMI reports two independent conclusions:

- **Maturity level (1–5):** how independently and consistently the designer thinks, executes, and demonstrates impact.
- **Professional profile:** where the designer's strongest demonstrated contribution currently sits.

Candidate profiles: Craft & Interaction Designer, Research-led Designer, Product-oriented Designer, Systems & DesignOps Designer, Technical Design Architect, AI & Automation Innovator, Design Leader & Facilitator, and Hybrid / Emerging profile.

A designer can have any profile at any maturity level. A Systems & DesignOps profile does not automatically mean Level 4; strategic language alone does not prove execution or impact. Choose a primary profile only when evidence distinguishes it from alternatives; otherwise use Hybrid / Emerging. Missing evidence is unknown, not proof of weakness. Profile labels are provisional, not fixed personality types.

See [PROMPT.md](./PROMPT.md#7a-evidence-based-professional-profile-classification) for rules and [PROFILE_CLASSIFICATION_TESTS.md](./PROFILE_CLASSIFICATION_TESTS.md) for calibration scenarios.

## Personal development cycle

**Assess → Prioritize → Plan → Practice → Apply → Receive feedback → Reflect → Reassess → Adapt**

Track learning progress, behavioral progress, and outcome progress separately. Completing a course or attempting an activity is not sufficient evidence of improved professional performance.

## Visual output standards

The complete written assessment and personal development plan must be delivered before asking the user to choose a visual. The only options are:

- **A — JPG infographic:** a high-resolution, portrait editorial report using the canonical warm-neutral style.
- **B — Interactive HTML dashboard (Claude recommended):** a responsive dashboard with competency scores, evidence/confidence details, development priorities, and the 30/60/90-day roadmap. Claude may handle this workflow more reliably, but support is not guaranteed in every AI environment.

The user receives only the selected format unless they explicitly request both. Both formats must use the completed report's final numerical dataset as their **single source of truth**. Do not create a visual before the written assessment is complete.

### Canonical JPG/JPEG style

Every confirmed/requested JPG/JPEG infographic uses this default style without requiring another style selection:

- Warm off-white background, deep navy typography, generous whitespace, thin dividers, and a consistent editorial grid.
- Blue current-profile/current-state data, magenta or pink target data, and restrained green emphasis for strengths.
- Verified personal header and assessment date; report title and overall score; radar comparison; eight aligned competency score rows; three key insights; current-to-next-level transition; short-, medium-, and long-term roadmap; restrained closing recommendation.
- Reference imagery may guide **visual style only**. Never copy its names, dates, scores, targets, or claims. All displayed content must come from verified subject information and the written assessment.

### Rendering and file integrity

Use the final numerical dataset as the source of truth; validate values before rendering and inspect the composed result where tools permit. For text-heavy charts and report layouts, deterministic HTML/CSS/SVG, Canvas, vector/document tooling, or Python/PIL rendering is preferred when available. These are internal rendering methods; the requested deliverable remains a JPG/JPEG, not HTML source code.

A PNG must be genuinely converted to JPEG before being labeled JPG. Never use a file extension to misrepresent the actual format. If conversion, rendering, or image inspection is unavailable, disclose the limitation rather than claiming successful export or inspection.

## Validation and legacy checklist

The profile scenarios are qualitative calibration cases; the repository's automated checks validate that key guardrails and scenario coverage remain present, but they do **not** run an AI model or prove runtime classification accuracy. Model behavior still requires repeated evaluation against the scenarios.

`ux-maturity-checklist.tsx` is a separate legacy six-level checklist. Its completion percentage is a task-completion heuristic, not a DMI maturity score, and its six levels do not map to DMI's five-level model. Do not use it as a substitute for the evidence-based assessment. Reconcile or retire it if the repository intends to maintain only one active maturity model.


## Career Radar and mentorship synthesis

Career direction is a mandatory analysis in the canonical prompt, not an optional add-on and not the eight-domain competency radar chart. The complete report includes an evidence-led career trajectory, current positioning, market signals with dates where research is performed, distinct scenarios and trade-offs, a mentor interpretation, falsifiable 30–90-day experiments, and a reassessment note. Missing evidence must be identified as unknown; it must not be fabricated.

The report's **Section 9 — Longer-Term Career Development** is one of the 15 numbered report sections. The separate **Prompt Section 9 — Personal Goals, Motivation & Career Direction** is an additional synthesis instruction that connects career history, current goals, market context, scenarios, and mentorship. The two labels refer to different layers of the prompt and should not be conflated.

For each visual format, Career Radar must have its own readable module populated from the same canonical data as the written report. It must not be removed merely because the evidence is incomplete. See the [feature-parity and regression audit](./FEATURE_PARITY_MATRIX.md).

## Feature preservation and validation

`FEATURE_PARITY_MATRIX.md` records mandatory DMI capabilities, their canonical sources, and the checks protecting them. Review it whenever the prompt, output format, scoring, career synthesis, or delivery workflow changes.

GitHub Actions runs structural regression tests against repository text. Those tests help catch accidental deletion of required instructions; they do **not** prove an AI run completed the assessment, a JPG was rendered and inspected, or an HTML dashboard works in a browser. Report runtime checks as PASS only when they were actually performed; otherwise label them UNVERIFIED.
